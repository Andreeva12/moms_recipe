# AutoTesting — автотесты админ-панели MomsRecipes

Автоматизированное тестирование админ-панели **MomsRecipes**
(https://sandbox.momsrecipes.fun/, sandbox-окружение) на **Playwright Test**
(JavaScript). Покрывает как UI (админка), так и часть API.

## Требования

- Node.js 18+
- Установленные зависимости: `npm install`
- Установленные браузеры Playwright: `npx playwright install chromium`

## Настройка

Скопируйте `.env.example` в `.env` и укажите реальные данные для входа в
sandbox-админку:

```bash
cp .env.example .env
```

| Переменная       | Назначение                                  |
|------------------|----------------------------------------------|
| `BASE_URL`       | адрес админки (`https://sandbox.momsrecipes.fun`) |
| `ADMIN_LOGIN`    | логин администратора для входа в тестах       |
| `ADMIN_PASSWORD` | пароль администратора                         |

**`.env` не должен попадать в git** — он в `.gitignore`. Если случайно
закоммитили реальные данные, считайте пароль скомпрометированным и смените
его в самой админке, а не просто удаляйте файл из репозитория.

## Запуск

```bash
# все тесты (UI + API)
npx playwright test

# один файл
npx playwright test tests/ui/orders.spec.js

# конкретный проект
npx playwright test --project=chromium
npx playwright test --project=api

# с отчётом в браузере после прогона
npx playwright show-report
```

`package.json` не содержит npm-скриптов — команды `playwright` запускаются
напрямую через `npx`.

## Структура проекта

```
pages/          — Page Object Model, один класс на раздел админки
tests/ui/       — UI-тесты (Playwright + Chromium, 1920×1080)
tests/api/      — API-тесты (запросы напрямую к бэкенду)
```

Конфигурация — `playwright.config.js`: `baseURL` для UI —
`https://sandbox.momsrecipes.fun`, для API-проекта — с суффиксом `/api`.
`fullyParallel: false`, retries и число воркеров зависят от `CI`.

## Запуск

Автоматического запуска (CI) в проекте нет, тесты запускаются только
вручную: `npx playwright test`. Отчёты никуда не отправляются.

## Что покрыто

Покрыты почти все разделы админки: Заказы, Покупатели, Товары, Промокоды,
Бонусы (лимиты, приветственные, логирование изменений), Отзывы, Контрольные
вопросы, Чат, Настройки кэшбэка, Доставка, Филиалы, Пользователи, История
кэшбэка/промокодов, каталожная таксономия (Разделы/Категории товаров,
Рецепты/Категории рецептов), Сторис, Баннеры, Розыгрыши, Жетоны,
Содержание, Импорт, а также часть API (доставка по зонам, данные
покупателя, филиалы).

**Важно про разделы с "живым" конфигом** (`/bonus-settings`, `/delivery`,
`/import`, `/settings`) — тесты там **read-only**: только чтение и
проверка отображения, без единого сохраняющего/мутирующего клика, чтобы
не сломать реальные настройки, влияющие на весь sandbox.

### Осознанно не покрыто (пропущено, не забыто)

- `dashboard.spec.js` (Главная) — весь набор под `.skip`
- `admin-edit-bonus.spec.js`, E2E-сценарии бонусов (`bonus-ui*`,

- `duble.spec.js`, `ORTO_SAI_STORE.spec.js` (API) — под `.skip`

## Особенности / грабли, на которые уже наступали

- **Гонка данных**: часть страниц админки (модалки, формы настроек)
  становятся `visible` раньше, чем Vue реально подгружает в них данные.
  Если тест падает на "пустом" значении сразу после открытия — почти
  всегда нужно дождаться конкретного поля/значения, а не просто
  видимости контейнера.
- **`test.beforeEach`/`test.afterEach` не имеют модификатора `.skip`** —
  только `test.skip()` и `test.describe.skip()`.
- Тесты на известные, ещё не исправленные баги фронтенда называются с
  суффиксом "(дефект)" и намеренно проверяют текущее (баговое) поведение
  — если баг починят, такой тест упадёт и напомнит его актуализировать.
